B-TREE VISUALIZER

The index structure inside every real database (Postgres, MySQL, SQLite). Insert keys and watch nodes split — the exact moment a database grows a new level. This is what "build your own database" produces.

order m = 4 (max 3 keys / node)height 1nodes 1keys 0
Ready. Insert some keys — try 10, 20, 5, 6, 12, 30, 7, 17.
What's happening: a B-tree keeps keys sorted across fixed-size nodes. When a node overflows (4th key here), it splits in two and pushes the middle key up to the parent — that split can cascade all the way to the root, growing the tree one level. Search walks down one path: O(log n) disk reads, which is why databases use it. The full implementation is ~120 lines below — open devtools → sources.

Try: insert keys 1–20 in order (worst case), then reset and insert them shuffled. Watch how splits keep the tree balanced either way.
