PIPELINE RUNNER

A miniature CI system in one file: parse → schedule → execute → report. Edit the pipeline, hit run, and watch stages stream logs like GitHub Actions. This is what "build your own CI runner" produces.

What's happening: the "YAML" is parsed into a stage DAG, stages run sequentially (a real runner would fan independent stages out to workers), each command streams timestamped log lines, and a non-zero exit fails the stage and stops the pipeline — the core semantics of every CI system. Commands containing fail/error simulate failure; everything else is a simulated shell. Real runners add containers, caching, and artifact storage on top of exactly this loop.
